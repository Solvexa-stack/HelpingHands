# 10 — Continuous Integration

## The regression safety gate

The API e2e suite (`apps/api/test/`) is the **backward-compatibility contract**
for the modernization roadmap: it freezes the project → study → vote →
approval lifecycle, both donation channels (QR physical + Stripe/PayPal
webhooks), the execution & financial path, and the full auth/roles matrix.
No wave may merge a change that breaks it
(see `workspaceroadmap/backlog/BACKLOG_W0_FOUNDATIONS.md`, Epic W0-E1).

Workflow: [`.github/workflows/e2e.yml`](../.github/workflows/e2e.yml)

## When it runs

- Every **pull request** (any target branch)
- Every **push to `main`**
- Superseded runs on the same ref are cancelled (`concurrency`)

## What it does

1. Starts service containers: `postgres:16-alpine` and `redis:7-alpine`
   (Redis is required — the API's Bull queues connect at boot).
2. `pnpm install --frozen-lockfile` + Prisma client generation.
3. Runs `pnpm test:e2e`. The harness creates its own `helping_hands_test`
   database (never a shared/dev one), applies all migrations, seeds the four
   test accounts, and fully resets state between suites — see
   `apps/api/test/README`-level docs in `docs/commands.md` → "E2E Tests (API)".

## Failure artifacts

When the suite fails, the run uploads `e2e-failure-artifacts-<run id>`
(kept 14 days):

- `e2e-output.log` — the complete jest output
- `test-db-dump.sql` — a `pg_dump --clean --if-exists` of the test database
  at the moment of failure, for replaying the broken state locally:

```bash
docker compose up postgres -d
docker exec -i helping_hands_db psql -U postgres -c 'CREATE DATABASE debug_e2e'
docker exec -i helping_hands_db psql -U postgres -d debug_e2e < test-db-dump.sql
```

## Making it a required check (one-time repo setting)

The workflow alone does not block merges — branch protection does. A repo
admin must enable it once (Settings → Branches → Branch protection rules →
`main`):

- ✅ Require status checks to pass before merging
- Select the check **`e2e-regression-suite`** (it appears in the list after
  the workflow has run at least once on any PR)
- Recommended: ✅ Require branches to be up to date before merging

Or via the API:

```bash
gh api -X PUT repos/Solvexa-stack/HelpingHands/branches/main/protection \
  -F 'required_status_checks[strict]=true' \
  -f 'required_status_checks[contexts][]=e2e-regression-suite' \
  -F enforce_admins=true \
  -F 'required_pull_request_reviews=null' -F 'restrictions=null'
```

⚠️ The required-check name is the **job name** `e2e-regression-suite` in
`e2e.yml`. Renaming that job silently detaches branch protection — update
both together.

## Reproducing CI locally

```bash
docker compose up postgres redis -d
pnpm test:e2e                # identical entry point to CI
```

The suite must be green **twice in a row** from any starting state — the
harness owns its database and resets it; a second run proves that.
